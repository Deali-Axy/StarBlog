# 待办事项

## 文章图片路径规范化

当前前台的 `articleImageUrl` 仅作为旧内容迁移期间的过渡兼容。后续通过修改文章内容统一图片路径，完成迁移和图片检查后再移除前台兼容。

- [ ] 在迁移工具中将原文和译文的相对图片地址规范化为 `/media/blog/{原文ID}/...`，不绑定域名；保留外部网址和已有绝对路径，处理 `./`、反斜杠及历史 `.assets` 目录。
- [ ] 按 Markdown 结构识别图片引用，避免误改代码块、普通链接或示例内容；拒绝越出文章媒体目录的相对路径。
- [ ] 修改前备份原始正文和译文，支持预检并输出变更清单；确认除图片地址替换外，正文、译文及其关联信息保持一致。
- [ ] 核对规范化后的图片地址与服务器媒体文件，验证前台原文/译文、后台预览和 Feed 的图片显示，并补充迁移测试。
- [ ] 在内容迁移和图片检查通过后，移除前台 `articleImageUrl` 路径补齐逻辑及文章 ID 传递，调整测试以验证正文中的规范化图片地址可直接渲染。

## 部署方式演进

首次迁移部署允许使用应用发布包：本地构建 `starblog-{{ version }}.tar.gz`，上传服务器，应用通过目录挂载在各自的 Docker 容器中运行。此阶段不要求把应用代码构建成专用镜像；当前 command → SCP → SSH 流程属于过渡方案，部署准备状态见 [新版上线方案](production-rollout.md)。

- [ ] 首次迁移完成并验证稳定后，改为构建包含应用产物的专用 Docker 镜像，覆盖 API、Next.js 和提供管理后台静态文件的网关。
- [ ] 将 `ship.toml` 切回镜像发布流程：本地或 CI 构建并 push registry，服务器 pull image 后通过 Compose 更新容器。
- [ ] 使用明确的发布版本并记录镜像摘要，验证健康检查、版本切换和回退；数据库、媒体及私密运行配置继续独立持久化，不写入镜像。
- [ ] 镜像发布流程验证通过后，移除应用发布包上传、解压和应用目录挂载等过渡逻辑，更新部署文档。
